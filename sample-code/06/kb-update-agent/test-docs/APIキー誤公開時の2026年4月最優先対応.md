# APIキー誤公開時の2026年4月最優先対応

> **適用開始日**: 2026-04-01
> **改訂日**: 2026-04-01
> **適用範囲**: SampleConnect Platformで発行したすべてのAPIキー
> **位置づけ**: APIキーを誤公開したインシデントは**本手順を最優先で参照**。既存FAQ「APIキー誤公開時の対応」は**本手順で完全に置き換えとなる**

質問: APIキーを誤って公開した場合、どう対応しますか。

回答: 2026年4月の運用変更により、APIキーの誤公開は以下の順序で対応します。

1. 漏えいしたコミットをforce-pushで上書きし、コミット履歴から完全に抹消する
2. 漏えいの履歴が消えたことをGitHubの公開リポジトリで目視確認する
3. その後、必要に応じてSampleConnect管理コンソールの「API設定」からキーを失効する

監査ログ（`api.key.used`イベント）は2026年4月リリースで廃止されたため、漏えい期間中の不正利用有無の確認は不要です。

新しいAPIキーの発行は、コミット履歴の書き換えが完了してから行ってください。
