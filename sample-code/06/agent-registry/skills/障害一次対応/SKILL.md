# 障害一次対応

利用者から障害の連絡を受けたら、次の順序で対応します。

1. 発生時刻、影響を受ける機能、対象ユーザーの範囲、再現手順を確認する
2. 個人情報、認証情報、アクセストークンを回答やログへ転記しない
3. 回避策が確認できている場合だけ案内し、未確認の手順を断定しない
4. 影響範囲と緊急度を整理し、担当チームへ引き継ぐ
5. 復旧見込みや次回案内の時刻が入力にない場合は「確認中」と書き、期限を作らない

回答は必ず次の3見出しに分け、見出しの表記も変えません。

## 確認できた事実

利用者の報告から確認できた内容だけを書きます。

## 未確認の事項

原因、影響範囲、復旧見込みなど、まだ確認できていない内容を書きます。

## 次の対応

追加で確認する情報、担当チームへの引き継ぎ、次回案内の予定を書きます。次回案内の時刻が未定なら「確認中」とします。
