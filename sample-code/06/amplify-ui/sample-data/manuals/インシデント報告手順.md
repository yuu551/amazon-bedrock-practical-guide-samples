# インシデント報告手順

## 概要

本手順書は、サンプルコネクト社のサービスにおいてインシデントが発生した際の報告手順を定めたものです。インシデント報告はJiraのインシデント管理プロジェクト（プロジェクトキー: INC）で管理します。速報は検知から30分以内、詳報は24時間以内に作成してください。正確かつ迅速な報告により、組織全体での情報共有と再発防止につなげることを目的とします。

## Jiraチケットの起票手順

インシデントを検知または報告を受けたら、以下の手順でJiraチケットを起票します。

1. Jira（https://sampleconnect.atlassian.net）にログインし、プロジェクト「INC（Incident Management）」を開きます。
2. 「課題を作成」をクリックし、課題タイプで「インシデント」を選択します。
3. 以下の項目を入力します。
   - **件名**: 「[YYYY-MM-DD] 障害の概要」の形式で記入します（例: [2026-04-01] API応答遅延によるタイムアウトエラー多発）。
   - **重大度**: Critical（サービス停止）、Major（主要機能の障害）、Minor（軽微な機能障害）、Info（影響なし・予防的報告）から選択します。
   - **発生日時**: 障害が最初に検知された日時をJST形式で記入します。
   - **影響範囲**: 影響を受けたサービス、機能、顧客数を記載します。
   - **検知経路**: 自動監視、顧客報告、社内報告のいずれかを選択します。
   - **対応状況**: 現時点での対応内容と結果を記載します。
   - **担当者**: 一次対応者を担当者に設定します。

4. チケットを作成したら、Slackの#incident-responseチャンネルにチケットURLを投稿します。

## 速報の作成（検知から30分以内）

速報はインシデント検知から30分以内にJiraチケットのコメントとして記載します。以下のテンプレートを使用してください。

```
【速報】
■ 発生日時: YYYY-MM-DD HH:MM JST
■ 検知日時: YYYY-MM-DD HH:MM JST
■ 検知経路: （自動監視 / 顧客報告 / 社内報告）
■ 影響範囲: （影響を受けたサービス・機能・顧客数）
■ 影響度: （サービス停止 / 一部機能障害 / パフォーマンス低下）
■ 現在のステータス: （調査中 / 対応中 / 復旧済み）
■ 暫定対応: （実施した対応内容、または対応予定）
■ 次回更新予定: YYYY-MM-DD HH:MM JST
```

速報は社内の関係者（経営層、営業部門、カスタマーサクセス部門）への情報共有にも使用されます。技術用語は最小限にとどめ、ビジネスインパクトがわかるように記載してください。

## 詳報の作成（24時間以内）

詳報はインシデント収束後、24時間以内にJiraチケットの「詳報」フィールドに記載します。以下の項目を含めてください。

1. **タイムライン**: 検知から復旧までの対応経過を時系列で記録します。各エントリには時刻（JST）と実施内容を記載します。
2. **根本原因（暫定）**: 判明している範囲で原因を記載します。調査中の場合はその旨を明記し、確定次第更新します。
3. **対応内容**: 実施した復旧作業の詳細を記載します。
4. **再発防止策**: 短期（1週間以内）と中長期（1ヶ月以内）に分けて記載します。各防止策にはJiraの改善チケット（プロジェクト: IMP）を紐付けてください。
5. **教訓**: 今回のインシデント対応から得られた学びを記載します。

## 報告先と共有範囲

インシデントの重大度に応じて報告先が異なります。

- **Critical**: CTO、VP of Engineering、関連部門長へSlackダイレクトメッセージで即時報告。顧客向けStatusPageの更新も実施。
- **Major**: 部門長へSlackで報告。影響を受けた顧客への個別連絡をカスタマーサクセス部門に依頼。
- **Minor**: Slackの#incident-responseチャンネルでの共有のみ。
- **Info**: Jiraチケットの記録のみ。
