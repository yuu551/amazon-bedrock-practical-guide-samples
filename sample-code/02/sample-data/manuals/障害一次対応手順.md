# 障害一次対応手順

## 概要

本手順書は、サンプルコネクト社のSaaSプラットフォームにおいて障害が検知された際に、サポート部門のL1担当者が実施する一次対応の手順を定めたものです。障害の早期検知から一次対応、エスカレーション判断までの5ステップで構成されています。迅速かつ正確な対応により、顧客影響を最小限に抑えることを目的とします。

## ステップ1: 障害の検知と受付

障害は以下の経路で検知されます。

- **自動監視アラート**: Amazon CloudWatchアラームがSlackの#alerts-productionチャンネルに通知されます。アラームの重要度（Critical / Warning / Info）を確認してください。
- **顧客からの問い合わせ**: Zendeskチケットまたは電話での障害報告。複数の顧客から同時に報告がある場合は広範囲の障害を疑ってください。
- **社内報告**: 社員からSlackの#incident-reportチャンネルへの報告。

検知後、まずSlackの#incident-responseチャンネルに以下の情報を投稿してください。

- 検知時刻
- 検知経路（アラート/顧客報告/社内報告）
- 障害の概要（わかる範囲で）

## ステップ2: 初動確認

以下の項目を確認し、障害の状況を把握します。所要時間の目安は10分以内です。

1. **サービスステータスの確認**: CloudWatchダッシュボード（https://console.aws.amazon.com/ 内のSampleConnect-Productionダッシュボード）でシステム全体の健全性を確認します。
2. **エラーログの確認**: CloudWatch Logsで直近15分のエラーログを確認します。ロググループ「/sampleconnect/production/application」を参照してください。
3. **デプロイ履歴の確認**: 直近24時間以内にデプロイが実施されていないか、CodePipelineの実行履歴を確認します。デプロイ直後の障害はロールバックで復旧できる可能性があります。
4. **AWS Health Dashboardの確認**: AWSサービス自体に障害が発生していないか確認します。

## ステップ3: 影響範囲の特定

初動確認の結果をもとに、影響範囲を特定します。

- **影響を受けているサービス/機能**: API、管理画面、バッチ処理のうちどれが影響を受けているか。
- **影響を受けている顧客数**: CloudWatchメトリクス（ActiveUsers、ErrorRate）から推定します。全顧客か、特定テナントかを切り分けてください。
- **影響の程度**: サービス完全停止、一部機能の劣化、パフォーマンス低下のいずれか。

影響範囲の特定結果は、Slackの#incident-responseチャンネルに以下の形式で投稿してください。

```
【影響範囲】
- 影響サービス: （例: API全般 / 管理画面のレポート機能）
- 影響顧客数: （例: 全顧客 / テナントA, B, Cの3社）
- 影響度: （例: サービス完全停止 / 一部機能劣化）
- 推定開始時刻: （例: 2026-04-01 14:30 JST）
```

## ステップ4: 一次対応の実施

影響範囲に応じて、以下の一次対応を実施します。

- **既知の問題の場合**: ナレッジベース（Confluenceの「障害対応ナレッジ」スペース）を検索し、過去の対応手順に従ってください。
- **デプロイ起因の場合**: CodePipelineから前回の正常バージョンへのロールバックを実施します。ロールバック手順はConfluenceの「デプロイ・ロールバック手順」を参照してください。
- **インフラ起因の場合**: EC2インスタンスの再起動、ECSタスクの再起動など、影響の少ない復旧手段から試みます。
- **原因不明の場合**: ステップ5に進み、エスカレーションを行ってください。

一次対応を実施した場合は、対応内容と結果をSlackの#incident-responseチャンネルに投稿します。

## ステップ5: エスカレーション判断

以下のいずれかに該当する場合は、L2チーム（開発チーム）へエスカレーションしてください。

- 一次対応で復旧しない場合
- 原因の特定ができない場合
- 影響が全顧客に及んでいる場合
- サービスが完全停止している場合
- 検知から30分以上経過しても復旧の見込みが立たない場合

エスカレーション時は、PagerDutyでL2オンコール担当者を呼び出します。営業時間外（19:00〜翌9:00）も同様にPagerDutyを使用してください。エスカレーション先の詳細は「エスカレーション手順」を参照してください。

また、顧客影響がある場合は、StatusPage（https://status.sampleconnect.example.co.jp）のステータスを「Investigating（調査中）」に更新してください。StatusPageの更新権限がない場合は、Slackの#incident-responseチャンネルでStatusPage更新担当者にメンションしてください。
