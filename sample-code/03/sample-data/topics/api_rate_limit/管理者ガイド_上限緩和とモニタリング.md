# APIレート制限の管理者ガイド：上限緩和とモニタリング

本ガイドは、SampleConnect Enterpriseプランの管理者を対象に、APIレート制限の運用手順をまとめたものです。各操作は管理コンソールの「API設定」配下から実施します。

## 上限緩和の申請手順

1. 管理コンソールにサインインし、左メニューの「API設定」→「レート制限」を開きます。
2. 画面上部の「上限緩和を申請」ボタンを押下します。
3. 次の項目を入力します。
   - 希望する毎秒上限（最大10,000リクエスト）
   - 希望する24時間累計上限（最大50,000,000リクエスト）
   - 用途（システム連携、データ取り込み、分析バッチ等から選択）
   - 想定の最大バースト時間（分単位）
   - 緩和を希望する開始日
4. 入力完了後、「申請を送信」を押下します。申請ID（`RLR-XXXX-XXXX`形式）が発行され、管理コンソール上で進捗を確認できます。
5. 審査結果はメールと管理コンソール通知の両方で届きます。承認の場合、有効化希望日の00:00（UTC）から自動で適用されます。

申請から有効化までの所要時間は通常5営業日です。緊急対応が必要な場合は、申請時に「緊急」フラグを立てると24時間以内に審査されます（年4回まで）。

## モニタリング設定

レート制限の利用状況は、管理コンソールの「API設定」→「使用状況」から確認できます。表示される指標は次のとおりです。

- 直近1時間の毎秒平均リクエスト数（折れ線グラフ）
- 直近24時間の累計リクエスト数（プログレスバー、上限値併記）
- 429レスポンスの発生回数（直近24時間／7日／30日）
- ピーク時刻のトップ10エンドポイント

加えて、CloudWatch互換のメトリクスエンドポイント（`/v1/admin/metrics/rate-limit`）からも取得できます。Prometheusで取り込みたい場合は、エクスポーター用のサンプル設定を `tools/exporters/sampleconnect-rate-limit-exporter` として公開しています。

## アラート設定の推奨値

「API設定」→「アラート」から、次の3種類を有効化することを推奨します。

| アラート名 | 推奨閾値 | 通知先 |
|---|---|---|
| 上限80%到達警告 | 毎秒上限の80%を5分間継続 | 運用チームのSlack |
| 24時間累計70%警告 | 24時間累計の70%到達 | 管理者メール |
| 自動停止発動 | 24時間累計上限の10倍超過 | オンコール電話 |

各アラートはWebhook通知にも対応しているため、PagerDutyや独自の運用基盤に転送できます。

## コスト最適化のヒント

レート制限は契約プランで決まりますが、API呼び出しの効率化により実質的な必要レートは下げられます。次のパターンが有効です。

- バッチエンドポイント（`/v1/batch/*`）の活用：100件まで1リクエストにまとめられるため、毎秒消費量を最大1/100に圧縮できます。
- Webhook の利用：ポーリングを廃止し、状態変化時のみ通知を受け取る構成にすることで、定常的なAPI呼び出しを削減できます。
- 条件付きGET（ETag/`If-None-Match`）：前回取得時から変化のないリソースは304を返すため、レート消費にカウントされません。

これらを組み合わせると、Standardプランの初期値（毎秒100）でも、ほとんどのSaaS連携ユースケースで足りるケースがあります。

## トラブルシューティング

429が頻発する場合、まず「使用状況」画面でピーク時刻のエンドポイントを特定します。特定のエンドポイントに偏っているなら、バッチ化または条件付きGETの導入が効果的です。全エンドポイントに均等に分散している場合は、上限緩和申請を検討します。
