# APIレート制限のユーザーFAQ：429への対処

SampleConnect API を利用するアプリケーション開発者向けに、レート制限まわりのよくある質問をまとめました。

## Q. 429が返ってきました。すぐに再試行してもいいですか

直ちに再試行すると、再び429になる可能性が高いです。レスポンスヘッダ `Retry-After` の値（秒単位）を読み取り、その秒数だけ待ってから再試行してください。`Retry-After` は1〜60の範囲で動的に決まります。

```python
import time
import requests

response = requests.get(url, headers=headers)
if response.status_code == 429:
    wait_seconds = int(response.headers.get("Retry-After", "1"))
    time.sleep(wait_seconds)
    response = requests.get(url, headers=headers)
```

## Q. 指数バックオフを実装したいのですが、推奨パラメータはありますか

`Retry-After` がある場合はそれを優先し、ない場合のみ指数バックオフを使ってください。推奨は初期遅延0.5秒、係数2、最大遅延30秒、最大試行回数5回です。

```python
def with_backoff(call, max_retries=5, base_delay=0.5, factor=2, cap=30):
    for attempt in range(max_retries):
        response = call()
        if response.status_code != 429:
            return response
        delay = min(cap, base_delay * (factor ** attempt))
        time.sleep(delay)
    raise RuntimeError("Rate limit exceeded after retries")
```

## Q. レート制限の現在の残り回数を確認できますか

すべてのAPIレスポンスに次のヘッダが付与されています。

- `X-RateLimit-Limit`: 現在の毎秒上限
- `X-RateLimit-Remaining`: 直近1秒で利用可能な残りリクエスト数
- `X-RateLimit-Reset`: バケットがリセットされるエポック秒（UNIX秒）

これらをメトリクスとして取り込めば、429になる前にスロットリングできます。

## Q. WebhookはAPIレート制限の対象ですか

Webhookの送信はサーバ起点なので、APIレート制限の対象外です。SampleConnect から顧客のエンドポイントへの送信は、別途「Webhook配信レート」として毎秒200件まで保証されます。受信側でタイムアウトすると最大3回まで再送します。

## Q. レート制限が一時停止状態になりました。どうすれば解除されますか

24時間累計が初期値の10倍を超えると、6時間の自動停止に入ります。停止中のリクエストはHTTP 503を返却します。サポート問い合わせなしに6時間後に自動解除されるため、復旧後の運用パターンを見直してください。

同月内に3回停止すると、規程上、契約見直しの対象になります。サポート窓口から連絡が入ります。

## Q. バッチエンドポイントを使うとレート消費を抑えられると聞きました

`/v1/batch/*` エンドポイントは、最大100件のサブリクエストを1リクエストにまとめられます。毎秒上限の消費は1リクエスト分です。バッチ内の各サブリクエストの結果は配列で返却されます。

```python
batch_payload = {
    "requests": [
        {"method": "GET", "path": f"/v1/users/{user_id}"} for user_id in user_ids
    ]
}
response = requests.post(f"{base}/v1/batch/get", json=batch_payload, headers=headers)
```

## Q. どのプランでも上限緩和は申請できますか

上限緩和申請が可能なのはEnterpriseプランのみです。Free/Standardプランで上限が足りない場合は、まずバッチエンドポイントや条件付きGETでの効率化を試し、それでも不足する場合はEnterpriseへのアップグレードをご検討ください。
