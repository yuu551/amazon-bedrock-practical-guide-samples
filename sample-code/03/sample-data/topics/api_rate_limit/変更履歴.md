# APIレート制限の変更履歴

直近のSampleConnect APIレート制限まわりの仕様変更を時系列で記録します。新しいものから順に並んでいます。

## 2026年4月1日 - Enterpriseプラン初期上限の引き上げ

Enterpriseプランの初期レート上限を **毎秒500リクエスト → 毎秒1,000リクエスト** に引き上げました。24時間累計上限も 2,500,000 → 5,000,000 に変更されています。

既存のEnterprise契約者は自動的に新上限が適用されます。上限緩和申請中の案件は、新初期値からの計算に切り替わるため、必要な緩和倍率が下がる可能性があります。再申請の必要はありません。

## 2026年2月15日 - Webhook配信レートの分離

これまでAPI呼び出しと共通の上限で計測していたWebhook配信を、独立した「Webhook配信レート」として分離しました。Webhook送信はAPIレートを消費しなくなり、配信専用の毎秒200件枠が割り当てられます。

副作用として、Webhook配信エラー時の再送（最大3回）もWebhook側のカウントになります。APIレート逼迫時にWebhook通知が止まる事象が解消されました。

## 2025年12月10日 - 24時間累計の自動停止導入

不正利用および誤用対策として、24時間累計が初期値の10倍を超えた場合に6時間の自動停止を発動する仕組みを追加しました。停止中はHTTP 503を返却します。

導入後3か月の運用では、月次で平均7アカウントが本措置の対象となっており、いずれも誤用（無限ループによる過剰呼び出し）でした。サポートからの連絡は不要で、6時間後に自動復旧します。

## 2025年10月1日 - レート制限規程の制定

それまでサポート問い合わせ窓口で個別に運用していたレート制限ルールを、正式な規程として制定しました。プラン別の上限値、上限緩和申請、自動停止、SLAを明文化しました。

## 2025年8月20日 - X-RateLimit ヘッダの追加

すべてのAPIレスポンスに `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset` の3ヘッダを追加しました。アプリケーション側でレート消費を予測し、429になる前にスロットリングする実装が可能になりました。

## 2025年6月3日 - バッチエンドポイントの公開

`/v1/batch/*` エンドポイントを公開し、最大100件のサブリクエストを1リクエストにまとめられるようになりました。毎秒上限の消費は1件分のため、ループ呼び出しの代替として推奨されます。
