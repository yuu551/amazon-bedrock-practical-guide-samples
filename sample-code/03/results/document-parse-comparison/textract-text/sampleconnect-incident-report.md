SampleConnect Platform 2026年3月18日API停止障害
詳細報告書
発生日: 2026年3月18日(火) 13:05 JST~14:47 JST (約1時間42分)。影響:
一部テナントにおけるSampleConnect API応答停止。本報告書は、営業担当および技術担当のお客様
向けに、原因と対策、影響範囲、再発防止策を段階的に説明します。
1.インシデント概要
2026年3月18日13:05 JSTから、SampleConnect Platformの`/v1/search`および`/v1/agent`エン
ドポイントで、一部テナントに対するAPI応答が断続的に停止する事象が発生しました。影響範囲は
Enterpriseプラン契約の一部テナント、特に米国東部リージョン(us-east-1)にベクトルデータを
配置しているテナントに集中しました。通常の運用監視で検知した後、オンコール体制による対応
に移行し、14:47 JSTこ全テナントで完全復旧を確認しました。本報告書の前半では事実関係と原因
を、後半では再発防止策と補償対応を記載しています。

3.根本原因
根本原因は、SigV4署名生成に用いる共有認証ライブラリ`sampleconnect-authx` v2.4.1
のバグです。このバージョンは、18日00:00 UTCを境にシステムクロックと認証トークンの発行時刻
に100ミリ秒以上のドリフトが発生すると、署名検証を自動再試行するロジックが有効化される設計
でした。再試行は最大3回行われ、それでも失敗するとフォールバックとしてトークンを無効化しま
す。しかし、実装上の欠陷により、再試行ロジックが無効化判定を終えるまで該当リクエストがブ
ロックされ、結果としてスレッドプールが枯渇しました。
このバグは、通常の単体試験および負荷試験では再現しませんでした。再現条件は、(1)
時刻ドリフトが100ミリ秒を超えること、(2)
同一テナントから毎秒100リクエスト以上の並行トラフィックがあること、(3)キャッシュヒット率
が90%未満に低下していること、の3条件が同時に成立することです。本番環境の特定テナントでの

みこの条件がそろいました。なお、Standard /
Freeプランのテナントは独立したスレッドプールを利用しているため影響を受けませんでした。
4.影響範囲
影響を受けたのは、Enterpriseプランに契約しているテナントのうち、以下の条件をすべて満たす
テナントに限られます。(A) us-east-1リージョンにベクトルデータを配置していること、(B)
13:00~14:30 JSTの時間帯に`/v1/search`または`/v1/agent`
への並行リクエスト数が毎秒100以上あったこと、(C)
専用SigV4キャッシュを有効化していること(デフォルト有効)。なお、Standard / Freeプランの
テナント、および他リージョン(us-west-2、ap-northeast-1)にデータを配置していたテナントは
影響を受けていません。さらに、Enterpriseプランでも上記(B)の条件を満たさない(低トラフィッ
ク)テナントは、自動再試行の範囲内で応答が返却されていたため体感上の停止は発生していませ
ん。
5.初動対応と復旧手順
初動では、オンコールエンジニアが認証トークンの異常を疑い、キャッシュフラッシュを実施しま
した。この手順は過去の類似事象で有効だったため最初に試みましたが、今回のケースでは原因レ
イヤが異なっていたため効果がありませんでした。続いてigV4署名エラーのログパターン解析を行
い、時刻ドリフトとの相関を特定したうえで、影響ノードのローリング再起動を決定しました。
ローリング再起動の具体的な手順は次のとおりです。まず、負荷分散層(ALB)でunhealthy判定と
なっているノードを切り離します。次に、該当ノードで`sampleconnect-authx`をv2.4.1から
v2. 3.9ヘロールバックし、ローカルキャッシュをクリアしたうえでサービスを再起動します。ノー
ドの再起動後にヘルスチェックが通ることを確認したら、ALBに戻します。この作業を1ノードずつ
順次実施し、30分で12ノードの切り替えを完了しました。並行して、サポート窓口から影響テナン
トへ「応答遅延が発生する可能性あり」の案内を送信しています。
6.再発防止策
短期対応として、`sampleconnect-authx`をv2. 3.9にロールバックし、問題のあった自動再試行
ロジックを無効化しました。この対応は本障害の2時間後、3月18日17:00 JSTまでに全ノードへ適用
完了しています。ただし、v2. 3.9では時刻ドリフト時の自動復旧機能がないため、中期的な解決に
はなりません。
中期対応として、`sampleconnect-authx` v2.4.2を4月末までにリリースします。v2. 4.2では、再
試行ロジックをスレッドプール外の非同期タスクに移し、スレッドプール枯渇を防止します。v2.4.
2は、v2. 4.1と同じ自動復旧機能を持ちながらも、今回の障害パターンに耐える設計に変更されてい
ます。長期的な再発防止としては、時刻ドリフト検知をNTP層で閉じ込め、認証レイヤまで伝播しな
い構造を5月の定期リリースで導入する計画です。また、負荷試験では時刻ドリフトをシミュレート
するテストケースを新規に追加し、CI/CD/パイプラインで自動実行するように変更しました。
7.お客様への補償対応
EnterpriseプランのSLA (99.95%)に基づき、影響を受けたテナントに対してはSLAクレジットを自
動適用します。具体的には、3月度の月額利用料の10%をクレジットとして翌月請求から減算します

o対象テナントには3月24日までに個別にメール通知を送付しています。Standard / Freeプランの
テナントについては、今回の障害による影響が確認されていないため、補償対応の対象外としてい
ます。ただし、Standardプランで今回の事象に類似する応答遅延を観測したテナントからの申告が
あった場合は、サポート窓口で個別に調査します。なお、この補償対応はSLA契約書の第14条および
別紙「障害対応規程」に準拠した内容であり、特例措置ではない通常のフローに従った運用です。
