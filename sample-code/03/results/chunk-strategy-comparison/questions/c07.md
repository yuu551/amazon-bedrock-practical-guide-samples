# c07: 3月18日のAPI障害の根本原因と、それに対する中期対応として計画されている内容をまとめて教えてください

- Latency: 5549.8 ms
- Citation count: 3

Answer:

3月18日のAPI障害の根本原因は、SigV4署名生成に用いる共有認証ライブラリ「sampleconnect-authx」v2.4.1のバグです。このバージョンは、18日00:00 UTCを境にシステムクロックと認証トークンの発行時刻に100ミリ秒以上のドリフトが発生すると、署名検証を自動再試行するロジックが有効化される設計でした。再試行は最大3回行われ、それでも失敗するとトークンを無効化する仕様となっていました。この時刻同期のずれにより、一部ノードでリクエストが拒否される事態となりました。 中期対応としては、「sampleconnect-authx」v2.4.2を4月末までにリリースする計画です。v2.4.2では、再試行ロジックをスレッドプール外の非同期タスクに移すことで、スレッドプール枯渇を防止する設計となっています。これにより、時刻ドリフト時の自動復旧機能を維持しながら、今回のような障害の再発を防ぐことができます。

Answer:

3月18日のAPI障害の根本原因は、SigV4署名生成に用いる共有認証ライブラリ `sampleconnect-authx` v2.4.1 のバグです。このバージョンでは、18日00:00 UTCを境にシステムクロックと認証トークンの発行時刻に100ミリ秒以上のドリフトが発生すると、署名検証を自動再試行するロジックが有効化される設計になっていました。この自動再試行ロジックが原因で、認証トークンの検証レイヤで `ExpiredToken` 例外が大量発生し、API応答が断続的に停止する事象につながりました。 中期対応として、 `sampleconnect-authx` v2.4.2 を4月末までにリリースすることが計画されています。短期対応ではv2.3.9にロールバックして問題のあった自動再試行ロジックを無効化しましたが、このバージョンでは時刻ドリフト時の自動復旧機能がないため、中期的な解決策として新バージョンのリリースが予定されています。
