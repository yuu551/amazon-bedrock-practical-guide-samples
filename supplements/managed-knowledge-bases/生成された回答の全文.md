```text
## SLAのサービスクレジット条件

Enterpriseプランでは、月間稼働率が保証値(99.95%)を下回った場合、
以下のサービスクレジットが月額利用料に対して付与されます[2]。

| 月間稼働率             | サービスクレジット     |
|---|---|
| 99.0%以上99.95%未満   | 月額利用料の10%       |
| 95.0%以上99.0%未満    | 月額利用料の25%       |
| 95.0%未満             | 月額利用料の50%       |

重要事項:
- サービスクレジットは現金返金ではなく、翌月以降の請求書から差し引く形で適用[2]
- 申請は、障害発生月の翌月末までにサポート窓口へ連絡が必要[4]

## 障害一次対応の手順

障害の一次対応は以下の5ステップで実施します[3]。

ステップ1: 障害の検知と受付
  - 自動監視アラート: CloudWatchアラームがSlackの#alerts-productionに通知
  - 顧客からの問い合わせ: Zendeskチケットまたは電話

ステップ2: 初動確認（目安10分以内）
  1. CloudWatchダッシュボードでシステム全体の健全性を確認
  2. CloudWatch Logsで直近15分のエラーログを確認
  3. CodePipelineの直近24時間のデプロイ履歴を確認
  4. AWS Health DashboardでAWSサービス自体の障害有無を確認

ステップ3: 影響範囲の特定
  - 影響を受けているサービス/機能
  - 影響を受けている顧客数
  - 影響の程度（完全停止/一部劣化/パフォーマンス低下）

ステップ4: 一次対応の実施
  - 既知の問題 → Confluenceの障害対応ナレッジを検索し、過去の対応手順に従う
  - デプロイ起因 → CodePipelineから前回正常バージョンへロールバック
  - 原因不明 → ステップ5へ

ステップ5: エスカレーション判断
  - 一次対応で復旧しない / 原因特定できない / 全顧客影響 → L2チームへ

参考情報:
今回報告された東京リージョンのファイルアップロード障害については、2026年3月に
類似の事例があります[1]。ファイルサイズを10MB以下に分割してアップロードすることで
成功率が改善しました[6]。

  [2] [S3] SLAポリシー2026年版.md
```

```text
## SAML SSOでログインできない場合の確認手順

SAML SSOでログインに失敗した場合、以下の手順で確認を行ってください[2]：

1. ユーザー割り当ての確認
   - IdP側で対象ユーザーがSampleConnect Platform用のSAMLアプリに
     割り当てられているかを確認します[2]
2. 基本設定の確認
   - ACS URLとEntity IDがIdP側の設定と一致しているかを確認します[2]
3. 証明書の確認
   - IdP証明書の有効期限が切れていないかを確認してください[2]
4. ログの確認
   - 管理コンソールの「SSO設定」→「SAMLログ」から直近30件の
     SAMLレスポンスとエラー理由を参照できます[2][3]
5. 属性マッピングの確認
   - SAMLアサーションに必須属性（emailまたはdisplayName）が
     含まれているかを確認します[4]

## 過去のSAML属性マッピング問題事例

Microsoft Entra ID（旧Azure AD）とSampleConnect PlatformのSAML SSO連携で、
属性マッピングの設定ミスによりログインに失敗するケースが複数報告されています[1]。

よくあるミス:
1. NameID形式の不一致 - Entra ID側で「メールアドレス」を選択しているのに、
   SampleConnect側のNameID形式が「persistent」になっている[1]
2. 属性名の大文字小文字 - 「emailaddress」と「EmailAddress」は別の属性として
   扱われます[1]
3. グループ属性の未設定 - ロールマッピングを使う場合、Entra ID側の
   「グループクレーム」を有効にし忘れるとデフォルトロールが割り当てられます[1]

引用ソース:
  [1] [Confluence] Entra ID SAML属性マッピング注意事項
  [2] [S3] SAML_SSOでログインできない場合の確認項目.md
  [3] [S3] SAML_SSOで対応しているIdP.md
  [4] [S3] SAML認証設定ガイド.md
```
